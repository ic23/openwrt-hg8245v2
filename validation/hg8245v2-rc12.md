# HG8245V2 RC12 · установка с заводской прошивки, обновление из LuCI и USB

Первую установку RC12 проверили на Huawei HG8245V2 (board 1 / PCB 3, NOR 16 МиБ) с заводской прошивкой Huawei `V100R003C00SPC106B176` и загрузчиком U-Boot 1.1.4. В каталоге `artifacts/hg8245v2-rc12` находятся файлы выпуска и `SHA256SUMS`.

## Первая установка

### Сохранение заводского дампа

Перед первой записью сохраните на ПК все 16 МиБ NOR своей платы. В дампе находятся серийный номер, MAC, калибровка Wi-Fi и настройки оператора. Сохраните файл в личном архиве.

1. Соедините ПК с LAN1 и задайте проводному адаптеру ПК `192.168.0.1/24`. Поместите `hg8245v2-rc12-recovery.bin` в каталог TFTP-сервера. В U-Boot загрузите recovery в RAM:

   ```sh
   tftp 0x92000000 hg8245v2-rc12-recovery.bin
   bootm 0x92000000
   ```

2. На ПК из каталога проекта запустите приёмник. Файл назначения должен быть новым:

   ```powershell
   python tools/hg8245_factory.py firmware_current/hg8245-fullflash.bin --receive-backup 192.168.0.1
   ```

3. Когда ПК напишет `Waiting`, в UART **OpenWrt recovery** выполните:

   ```sh
   ip addr add 192.168.0.20/24 dev br-lan
   hg8245-factory-backup | nc 192.168.0.1 8245
   ```

4. Дождитесь сообщения ПК `Verified 16777216 bytes` с SHA-256. Приёмник проверяет загрузчик, разметку, BoardInfo, область калибровки и CRC контейнеров. После успешного сохранения перезагрузите роутер и остановите автозагрузку в U-Boot для запуска установщика.

### Запись RC12 поверх заводской прошивки

1. Подключите ПК кабелем к LAN1. Проводному адаптеру ПК задайте `192.168.0.1/24`. Разместите `hg8245v2-rc12-installer.bin` в каталоге TFTP. На ПК из каталога проекта запустите HTTP для передачи системного образа:

   ```powershell
   python -m http.server 8000 --bind 192.168.0.1 --directory artifacts/hg8245v2-rc12
   ```

2. В UART, в приглашении U-Boot `hisilicon #`, выполните:

   ```sh
   tftp 0x92000000 hg8245v2-rc12-installer.bin
   bootm 0x92000000
   ```

3. В приглашении **OpenWrt** установщика выполните:

   ```sh
   ip addr add 192.168.0.20/24 dev br-lan
   wget -O /tmp/system.bin http://192.168.0.1:8000/hg8245v2-rc12-factory-region.bin && sysupgrade -T -n /tmp/system.bin && echo IMAGE_OK
   ```

4. Убедитесь, что заводской дамп сохранён на ПК и установщик вывел `IMAGE_OK`. Следующая команда запишет RC12 в системную область NOR. Оставьте питание включённым до перезагрузки.

   ```sh
   sysupgrade -n /tmp/system.bin
   ```

5. На ПК верните получение адреса по DHCP. После первой загрузки откройте `http://192.168.1.1/`. Системные разделы занимают диапазон от `0x060000` до `0xadffff` включительно. U-Boot, flashcfg, syspara с серийным номером и MAC, minisystem, jffs2cfg и reserved с калибровкой Wi-Fi лежат вне этого диапазона. Копия голосовой прошивки находится в системном образе.

## Последующие обновления

Откройте **System → Backup / Flash Firmware → Flash image…**. Выберите файл следующего совместимого выпуска с окончанием `-sysupgrade.bin` и оставьте включённым **Keep settings and retain the current configuration**. Сверьте SHA-256 с `SHA256SUMS` выпуска, подтвердите и дождитесь перезагрузки. После сохранения настроек адрес LuCI остаётся прежним. Процедура использует Ethernet или Wi-Fi, UART и TFTP нужны для первой установки или аварийного восстановления.

Сохраняются стандартные настройки OpenWrt, в том числе изменённые файлы UCI, и файлы из `/etc/sysupgrade.conf`. В терминале установленной системы `sysupgrade -l` показывает список. Дополнительные пакеты, которых нет в новом образе, после обновления устанавливаются заново. На этой плате один системный слот. При потере питания в ходе записи восстановление выполняется через U-Boot и RAM-установщик.

## USB

Для первой проверки вставьте флешку с FAT32 или ext4. В LuCI откройте **System → Mount Points**, добавьте точку монтирования по UUID и примените. Из терминала список устройств показывает `block info`. Если в нём раздел флешки называется `/dev/sda1`, для однократной проверки чтения выполните:

```sh
mkdir -p /mnt/usb
mount -o ro /dev/sda1 /mnt/usb && ls -la /mnt/usb
umount /mnt/usb
```

У накопителя без таблицы разделов файловая система может быть прямо на `/dev/sda`. Используйте имя, показанное `block info`. В заводской прошивке `V100R003C00SPC106B176` функция `hw_drv_usb_gpio_clock_open(1)` в `hw_module_usb.ko` записывает единицу в GPIO58 для этой ревизии. Ветка для версии платы 5 выставляет обратный уровень и печатает сообщение с префиксом C02. Лог именно этой платы содержит обычное `usb1 gpio clock open`. Включены оба контроллера, EHCI на `0x40010000` и OHCI на `0x40020000`.

## Результат проверки выпуска

На ARM в QEMU с 50 МиБ памяти для Linux RAM-установщик принял релизную системную область, отклонил укороченную и испорченную копии и записал релиз в эмулированный NOR. Проверены все 16 МиБ, включая заводские разделы по обе стороны от системной области.

В отдельной проверке образ из установленной системы с прежним размером SquashFS обновили на RC12 с обработчиком нового формата. После холодной загрузки сохранились имя хоста в UCI и дополнительный файл, перечисленный в `/etc/sysupgrade.conf`. Файл вне списка исчез. Граница JFFS2 переместилась с `0x940000` на `0x9a0000`. Доступный размер раздела overlay у RC12 составляет 1,25 МиБ до накладных расходов JFFS2.

Из чистого установленного RC12 отдельно проверены HTTP-загрузка всех 7 782 644 байт в `cgi-upload`, ответ `valid=true, allow_backup=true`, проверка и запуск штатного sysupgrade через те же RPC, которые вызывает LuCI. SHA-256 загруженного файла совпал с манифестом. После перезагрузки восстановилось изменение в `/etc/sysupgrade.conf`. При обновлении с `-n` отдельно подтверждён сброс настроек. Образ с одним изменённым байтом проверку не прошёл.

Для проверки сохранения данных использовалось отображение копии NOR с геометрией стирания 128 КиБ и тестовое ядро ARM. Система распознала виртуальные USB Mass Storage с FAT32 и ext4. Записанные файлы прочитаны после размонтирования и повторного монтирования.

На реальном HG8245V2 владелец подтвердил установку RC12 поверх стока в NOR. После установки контроллер EHCI обнаружил флешку Netac OnlyDisk в режиме USB 2.0 High-Speed. Драйвер usb-storage передал её подсистеме SCSI, ядро определило ёмкость 14,5 ГиБ и обнаружило оба раздела, /dev/sda1 и /dev/sda2. Проверка чтения и записи файлов выше проводилась в QEMU.

В [UART-логе платы](hg8245v2-rc12-board-boot.txt) сохранилась строка инициализации драйвера Ethernet с пометкой `UNTESTED`. Это текст, встроенный в бинарник. Приём и передачу Ethernet, DHCP и доступ к LuCI проверяли на этой плате. [Результаты сетевых испытаний](hg8245-lan-wifi-luci-test.txt).

На предыдущих сборках голосового драйвера после настройки GPIO4[0] плата вернула ID `04 b3`. Владелец подтвердил звонок, отбой, интерком и SIP через Ethernet с передачей голоса в обе стороны. Испытаний связи SIP через оптический WAN и длительного разговора на установленном RC12 пока нет.

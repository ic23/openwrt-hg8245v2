# HG8245V2: заводские регистры SD5113 и их использование в RC12

Сведения относятся к Huawei HG8245V2 (board 1 / PCB 3) с заводской прошивкой `V100R003C00SPC106B176`. Адреса ниже физические, если явно не указан другой вид адреса. Для стока указаны бинарник и смещение инструкции. Для RC12 сверены DTB из образов `recovery` и `factory-region`, исходники порта и сообщения ядра с этой платы. [Загрузочный лог RC12](../../validation/hg8245v2-rc12-board-boot.txt)

## Коммутатор AR8316 и шина MDIO

В заводском U-Boot выводится `Extend LSW IS AR8316`. В RC12 ядро зарегистрировало `Atheros AR8316 rev. 1` на шине `43b0a000.mdio`. Порт 0 коммутатора соединён с CPU и передаёт трафик с метками VLAN. На обычной конфигурации RC12 соответствие гнёзд следующее. [Настройки портов платы](../../openwrt-target/target/linux/sd5113/base-files/lib/hg8245/board-info.sh) · [Настройки VLAN](../../openwrt-target/target/linux/sd5113/base-files/etc/uci-defaults/12_hg8245_lan_ports)

| Гнездо на корпусе | LAN1 | LAN2 | LAN3 | LAN4 |
| --- | ---: | ---: | ---: | ---: |
| Порт AR8316 в swconfig | 2 | 3 | 4 | 1 |
| Внутренний VID в RC12 | 101 | 102 | 103 | 104 |

В заводском `hw_ker_ar8316_lsw.ko` функция `hw_ar8316_lsw_init` читает регистр POSTRIP коммутатора по смещению `0x08`, выполняет `OR 0x5` и записывает результат обратно (`.text+0xc2c…0xc40`). Это устанавливает биты 0 и 2 с сохранением остальных битов. В обоих DTB RC12 узел `switch@0` содержит полное значение `qca,postrip = 0x80061b65`. По одной операции `OR` полное значение заводского регистра определить нельзя. [Описание AR8316 для этой платы](../../openwrt-target/target/linux/sd5113/files-6.6/arch/arm/boot/dts/hisilicon/hisilicon-sd5113-hg8245-ar8316.dtsi)

Контроллер MDIO в RC12 занимает `0x43b0a000`, размер окна `0xb04` байта. У регистра данных `+0x100` чтение и запись используют разные половины слова. В заводском `hi_mdio.ko` чтение возвращает биты 31–16 (`.text+0x804…0x80c`), запись заменяет биты 15–0 и сохраняет старшие 16 бит (`.text+0x9a0…0x9b0`). Так же работает драйвер RC12. [Драйвер MDIO](../../openwrt-target/target/linux/sd5113/files-6.6/drivers/net/mdio/mdio-sd5113.c)

## Передача Ethernet через SD5113

Окно передачи CPURTx начинается с `0x42100000` и занимает `0xd8` байта. В заводском `hi_eth.ko` бит 0 регистра `+0x10` сообщает о завершении передачи. Обработчик читает возвращённый адрес буфера из `+0x14` и сбрасывает бит завершения (`eth_reclaim_tx_buffer`, `.text+0x654…0x678`). При подготовке передачи заводской код вычитает `0x30000000` из указателя буфера (`.text+0x1aec`). В порте адрес для устройства получает Linux DMA API через `dma_map_single()`. [Драйвер Ethernet RC12](../../openwrt-target/target/linux/sd5113/files-6.6/drivers/net/ethernet/hisilicon/eth-sd5113.c)

## Таймеры, системное управление и watchdog

| Узел | Заводская прошивка Huawei | RC12 |
| --- | --- | --- |
| Системный таймер | Ядро использует страницу `0x16144000` и IRQ 4. Запись таблицы отображения находится в распакованном ядре по смещению `0x19474`, вызов регистрации IRQ — по `0x2857c`. | В обоих DTB узел `timer@16144000` имеет тип `arm,sp804`, размер `0x40` байта и IRQ 4. На реальной плате ядро вывело `Switched to clocksource arm,sp804`. |
| Дополнительный таймер | Модуль `hi_timer.ko` отображает другое окно, `0x16145000` длиной `0x40` байта (`.init.text+0x30…0x3c`), и запрашивает IRQ 5 (`.init.text+0xa8`, `+0xec`). | Для системного времени выбран первый таймер. |
| Watchdog | Ядро отображает 4 байта с `0x420000dc` и записывает ключи `0x55aa5a5a`, затем `0xaa55a5a5` (смещения `0xaad4…0xaae0` и `0xab0c…0xab18` в распакованном ядре). | Код платы обслуживает тот же регистр той же парой ключей. Штатный интервал обслуживания — 250 мс. Время до аппаратного сброса при прекращении обслуживания на этой плате не измерялось. |

Источники RC12 для таймера и watchdog: [дерево устройств](../../openwrt-target/target/linux/sd5113/files-6.6/arch/arm/boot/dts/hisilicon/hisilicon-sd5113-hg8245.dts) и [код платы](../../openwrt-target/target/linux/sd5113/files-6.6/arch/arm/mach-sd5113/board.c).

Сток обращается к странице системного таймера также из `hi_sysctl.ko`. В таблице модуля по файловым смещениям `0x1c64` и `0x1c68` лежат `0x16144000` и `0x000144b5`. В функции `hi_kernel_sysctl_tcm_func` инструкции `.text+0x5bc…0x5c4` используют эти поля и записывают `0x000144b5` по адресу `0x16144018`. Назначение этого значения при переключении TCM остаётся неизвестным.
